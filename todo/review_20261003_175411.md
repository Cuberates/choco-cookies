# Iteration 3 UI specification review

Updated: 2026-10-03 20:43:08 PDT

Specification: [specifications_iteration_3.md](./specifications_iteration_3.md).

Scope: review the current title-page card styling, button palette, footer content, and branding against iteration 3. This replaces the earlier general catalog review. Backend imports, database behavior, new pages, and new features are outside this review's scope.

## Findings

### P2 — The title-page card still has exaggerated rounding

Reference: `src/main/resources/static/css/catalog.css:403`.

The hero's `.hero-visual` still uses a 24px border radius; its `.featured-note` and the featured `.ball-card` components use 12px. Iteration 3 asks for visibly reduced title-page card rounding, but that adjustment has not been implemented.

Recommended change: reduce the hero card to approximately 8–12px and its inset card to approximately 6–8px. Keep the grid, image placement, and card contents intact. The specification does not prescribe an exact radius; these values are implementation suggestions. Apply a consistent smaller radius to the relevant title-page cards without flattening unrelated circular icon controls.

### P2 — Cyan action styling and white-on-cyan text remain

References: `src/main/resources/static/css/catalog.css:213`, `src/main/resources/static/css/catalog.css:481`, `src/main/resources/static/css/catalog.css:656`.

The primary action background still uses `--accent: #45d7ff`, and carousel buttons use the same cyan. The “See more” summary explicitly overrides its text to white. White against this cyan has a calculated contrast of approximately 1.69:1, confirming the blending issue described in the specification. The carousel's supplied white chevrons have the same background pairing.

Recommended change: use a neutral dark slate or charcoal action background with readable light text, including hover and focus states. Check Search, See more, carousel arrows, Apply filters, and any retained footer action. Keep the layout and core branding; a neutral action palette does not require redesigning every accent or asset.

### P2 — All explicitly excluded footer items are still present

References: `src/main/resources/templates/catalog.html:61`, `src/main/resources/templates/catalog.html:62`, `src/main/resources/templates/catalog.html:63`.

The footer still contains Reaction glossary, Ball selector, the entire About group, Privacy, Terms, Accessibility, and Instagram/YouTube social links. These directly conflict with the footer cleanup requirement.

Recommended change: remove these elements from the footer markup entirely. Do not merely hide them with CSS. Preserve retained footer links only where useful and keep the remaining layout balanced. Removing footer links does not require removing working dialogs or navigation elsewhere on the page.

### P2 — Footer branding and marketing remain more extensive than permitted

References: `src/main/resources/templates/catalog.html:57`, `src/main/resources/templates/catalog.html:59`, `src/main/resources/templates/catalog.html:63`.

The footer includes an email marketing callout, a bowling-ball brand mark, the LANE INDEX lockup, promotional equipment copy, an “Independent • no paid rankings” statement, and a copyright line. Iteration 3 calls for minimal, non-promotional branding limited to the application name itself and removal of unnecessary marketing content. The specification names the application Bowler's Journal; the implementation still identifies it as Lane Index.

Recommended change: simplify the footer to the application name and necessary retained navigation. Remove the newsletter callout, ornamental brand mark, promotional copy, and ownership-style wording. Use Bowler's Journal as the footer application name while keeping unrelated header/product branding changes outside scope.

There are no literal ™ or ® symbols in the current footer. The copyright symbol is not a trademark symbol and should not be reported as one. The `NRG™ Solid` text appears in a product card outside the footer, so the footer-only restriction does not require changing it.

## Focused implementation and verification

Use the existing `catalog.html` and `catalog.css`. Change `catalog.js` only if removing footer markup leaves an unconditional event binding to a deleted element. For example, deleting `#email-signup` without removing or guarding its listener at `catalog.js:115` would cause a JavaScript error during initialization. Do not add pages, features, database changes, or new import behavior.

After the visual changes:

1. Check hero and card rounding at desktop and mobile widths.
2. Check text and chevron contrast in default, hover, and focused button states.
3. Inspect the rendered footer for every excluded label, social link, and promotional element.
4. Exercise search, filters, See more, carousel controls, bookmarks, and retained navigation; confirm there are no JavaScript errors after footer elements are removed.
5. Run the relevant existing catalog tests and rebuild the application JAR.

Review method: current source inspection and color contrast calculation. No application files were changed, no new tests were run, and no live services were accessed for this review. The prior 12-test and desktop/mobile verification validates the earlier implementation, not completion of iteration 3.

Iteration 3 is not yet implemented. The required work is confined to smaller title-page card radii, a neutral action palette, and removal of the specified footer content and branding.
